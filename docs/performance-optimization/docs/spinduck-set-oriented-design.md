# SpinDuck 受限集合化转换引擎设计

> **技术基线**：Rust + `ogsql-parser` 公共 API + DuckDB 1.5.5；具体行为以当前 SpinDuck 解释器、规则注册表及守护测试为准。
>
> **文档状态**：设计及首个受限实现切片；当前落地范围见 §8.6，不代表完整首版已完成，尚无 `--set-oriented` 旗标。
> **首版目标范围**：全目录分析、受限静态单游标集合化、明确的等价证明与拒绝原因。动态模板、通用跨函数内联、异常行回放不属于首版。

---

## 1. 目标、等价契约与能力分期

### 1.1 目标

1. 默认关闭。关闭时不运行集合化 Pass，不改变原始编译产物与解释执行路径。
2. 开启时仅转换能够证明业务可观察行为等价的循环区域；无法证明就是不准入，而不是尝试近似改写。
3. 优化主体在全量源码注册完成后、执行之前完成。全目录用于解析调用与对象依赖，不意味着必须改写整个目录。
4. 保留原始 IR，生成独立优化产物；不原地覆盖唯一的 `IrProg`。
5. 以消除逐行解释与 SQL 往返为性能方向，不以预设业务过程必须转换成功作为准入标准。

### 1.2 等价对象

集合化首先相对于 **SpinDuck 原始执行路径**证明等价；GaussDB 兼容性是另外一层验证。不得借集合化静默修复或改变当前 SpinDuck 与参照数据库的已知差异。

在相同输入、规则、目录、有效对象结构和事务快照下，业务观察面包括：

- 目标及其他业务表的内容、重复行与 NULL；
- 返回值、OUT/INOUT，以及循环出口仍可读取的局部状态和游标状态；
- 可到达的错误码、故障域、处理器选择与错误消息契约；
- 日志、序列等副作用及其顺序；
- 提交、回滚边界和失败前已经持久化的数据。

第一版通过拒绝含不可证明异常、副作用和跨区域状态的循环来限制证明面，不承诺任意 PL/SQL 都能等价集合化。默认关闭和用户显式开启都不能替代等价证明。

以下内容必须单独披露，不宣称物理执行轨迹逐字相同：

- 优化后的 SQL 文本、执行次数、耗时及对应 trace 事件会变化，但实际执行不得从 trace 中消失。
- 解释器步数会减少；原始 PC 步数预算不是性能模式下的不变观察面。OFF 保留既有预算契约，ON 的预算用于实际执行 IR，不能声称相同步数阈值必然同成败。
- 资源耗尽、连接故障及并发事务调度不作逐点等价承诺；仍须传播实际错误并遵守顶层事务清理，不吞错、不自动重放。若用户依赖这些失败位置对应的行为，应使用 OFF。

### 1.3 分期

| 阶段 | 能力 | 当前承诺 |
| :--- | :--- | :--- |
| V1：受限静态集合化 | 单静态游标、单目标 INSERT、无区域内事务边界、已证明全定义表达式与单行查询 | 本文唯一实施范围 |
| V2：特定异常关系化 | 对具体查询的零行/多行结果、默认赋值和跳行建立错误与状态模型 | 后续独立设计、测试和评审，不承诺上线时间 |
| V3：动态模板 | 动态查询运行期准入、绑定和形状校验 | 延后；V1 保留原动态游标和动态 SQL |
| 单独研究：异常回放 | 含日志、约束失败、事务恢复的批处理 | 不视为 V2/V3 自动获得的能力，不承诺可普遍等价 |

### 1.4 首版明确不做

- 吞并循环内 COMMIT/ROLLBACK；不改变事务契约。
- 正常行先批量写入、异常行事后回放。
- `INSERT OR IGNORE`、失败后 Appender/SQL 重试、整事务重放。
- 一般多语句函数内联、过程调用消除、动态字符串反参数化。
- 嵌套循环、UPDATE/DELETE/MERGE、多表交替写、目标表读写相关循环。
- 为满足某个性能数字或业务例程名称而放宽准入。

## 2. 首版准入规则

准入对象是例程中的一个循环区域，不是整个例程的名字。首版只处理单入口、单出口的标准静态游标循环；外围语句原样保留。

| 检查面 | V1 允许 | 必须拒绝 |
| :--- | :--- | :--- |
| 控制流 | 标准 OPEN/FETCH/退出条件/尾回跳/CLOSE；可结构化的 IF/CASE | 动态游标、嵌套循环、任意 GOTO、提前 RETURN、非结构化控制流 |
| 事务 | 区域内无事务语句，外部事务边界位置不变 | 区域内 COMMIT/ROLLBACK；生成器自行补 COMMIT |
| 异常 | 区域不受可捕获其错误的 PL 处理器覆盖，获准的值计算与写入已证明不会产生数据相关错误 | 区域内异常处理器、覆盖区域的外层处理器、RAISE、需要保留错误行现场 |
| 状态 | 游标行、只读 IN 参数、已证明循环不变的局部值；每轮重新定义且出口不活跃的临时量 | 跨轮依赖；OUT/INOUT 修改；循环后读取被消除的赋值、记录或游标属性 |
| 写入 | 每条游标行至多一次、单目标普通 INSERT VALUES；必要时由明确的分支条件决定是否写入 | 多次 INSERT、多目标、UPDATE/DELETE/MERGE、未知目标或写后读依赖 |
| 查询 | 静态主游标；已证明每组输入恰好返回一行且求值全定义的只读查询 | 可能零行/多行的 SELECT INTO、通用相关子查询、Top-1、未知依赖 |
| 表达式 | 有类型和 NULL 证明的白名单；保留每次赋值转换 | 未知类型、潜在转换/溢出/除零错误、未证明的 SQL/PL 运算互换 |
| 调用 | 已验证的全定义、确定性 SQL 内建表达式 | CallRoutine、未证明的 FuncCall/宏、非空 fn_sites、一般多语句函数 |
| 目标结构 | 类型、精度及已支持约束足以证明全部输出可写入 | UNIQUE/PRIMARY KEY/CHECK/FK 等尚未支持的约束证明；未知默认值、生成表达式或其他副作用 |
| 行序 | 结果及所有被保留行为对插入顺序不敏感 | 依赖逐行顺序的业务语义；序列、随机数、时间敏感调用等 |

说明：

1. 不是所有数据库约束都不可能证明，而是 V1 不实现通用约束求解。NOT NULL、目标数值范围及转换同样必须有证明，不能因为没有主键就直接放行。
2. 每个省略的目标列也需证明默认值全定义、确定且没有副作用；未实现这类证明时只接受显式覆盖全部列的 INSERT。
3. 主游标对目标表的读取，包括视图、子查询、被调用表达式中的间接读取，都属于依赖检查面。不能只比较 SQL 文本中的表名 token。
4. 参数仅有声明类型不足以证明其值域；例如字符串日期、任意非 NULL 数字不自动获得安全日期运算或非零除数资格。
5. 因证明不足而不准入是正常结果。不得用当前样本数据没有异常替代对允许输入域的证明。

### 2.1 purchase 与 hz 过程的定位

`prc_trd_deal_purchase` 是反例与后续覆盖对象，不再预设为 V1 成功案例：

- 循环内含 COMMIT。
- 多个 SELECT INTO 依赖异常跳行或默认赋值。
- 维表候选集合含相关子查询、默认席位与证券类别优先级。
- 日志调用、潜在日期转换和 INSERT 失败需要单独证明。

因此该过程 V1 应保持原 IR；即使当前部署使用空日志桩，也不解除其余限制。`prc_trd_hz_byfund` 的动态内层游标与 UPDATE 段同样不属于 V1。

首个成功案例应是专门构造的最小静态循环，明确具备可证明的类型、写入和事务条件，而不是删改现有业务语料来迎合优化。

## 3. 修正后的等价规则

### 3.1 SELECT INTO：基数、NULL、错误分别建模

查询结果应概念性地表示为：`行数状态 + 列值及 NULL + 查询/赋值错误 + 对应控制流`。不得用单个 NULL 表示所有状态。

| 原查询结果 | 原行为 | 正确转换要求 |
| :--- | :--- | :--- |
| 0 行 | NO_DATA_FOUND | V1 不准入；后续按对应处理器建模 |
| 1 行且列为 NULL | 成功写入 NULL，之后遵循目标槽类型规则 | 保留 NULL，不自动赋默认值 |
| 1 行且列非 NULL | 按序写槽并执行每个目标的类型转换 | 保留各赋值边界 |
| ≥2 行 | TOO_MANY_ROWS，当前实现不写 INTO 目标 | V1 不准入；不能 LIMIT 1 |
| 查询或目标转换失败 | 按实际错误进入对应异常路径 | 不是缺行，不能用 COALESCE/TRY_CAST 掩盖 |

删除原方案中的 `COALESCE((原查询 LIMIT 1), default)` 通用规则。`WHEN OTHERS` 也不等同于“缺行时默认值”。

V1 的单行查询需要静态证明，例如受支持的无 GROUP BY 标量聚合且整个表达式全定义；其余形态只有唯一性与存在性都能从有效结构事实证明时才可加入白名单。仅有 UNIQUE 不保证存在一行。

不得在 V1 增加“先执行任意查询看看是否可优化”的隐式预执行通道。

### 3.2 相关查询：计数与排名基于完整候选集合

后续扩展 Lookup 必须先定义每组调用参数对应的候选关系，再在该关系上计算基数或排名：

`原游标行 → 完整关联参数域 → 候选关系 → 基数/排名 → 回接原游标行`

- `HAVING COUNT(*) = 1` 只有在候选关系恰好对应原查询结果时才有意义，不能直接对维表任意键分组。
- 保留 IN/EXISTS 的半连接语义，不得把子查询改成会放大行数的普通 JOIN。
- 游标行含重复值时仍须保留重复次数；参数域去重用于共享计算，不得去重最终输出。
- Top-1 要在当前参数对应的完整候选集合中排序，而不是先在维表上选首行。
- 排序并列、NULL 排序、排序规则和 ROWNUM 所在查询层次均需独立证明。不能添加原语义没有的 tie-breaker 来宣称等价。
- 聚合 SELECT 的输出行数不等于底层匹配行数，必须依据原查询形状判断。

V1 不实现通用相关 Lookup、范围关联、Top-1 转换；这些规则在证明与守护测试完成前只用于拒绝原因和后续设计。

### 3.3 表达式：类型转换与错误边界不可消除

每个符号值至少携带：值表达式、声明/计算类型、可空性、可证明值域、执行路径及潜在错误分类。

- 在每次原始赋值处保留 `coerce_for_slot` 对应的转换语义；不能只在最终 INSERT 统一 CAST。
- PL 数值运算与 DuckDB SQL 数值运算不得默认互换。整数除法、定标、精度、舍入、溢出和比较规则逐项建立白名单。
- TRY_CAST 只能用于原语义确实返回 NULL 的已证明规则；不能作为“避免整批报错”的通用措施。
- NULL 算术结果不自动代表异常。特别是 NULL 除数不能直接通过 `denom IS NOT NULL` 过滤掉。
- `NULLIF(denom, 0)` 改变除零行为，本身不是等价证明。V1 仅接受值域已证明不会产生原路径错误的除法，否则拒绝。
- 原表达式可能不执行的分支，不得因下推而新增可观察求值。

`RuleRegistry` 是规则事实源，不是任意表达式跨 SQL/PL 等价的证明。不得维护另一套隐式转换规则表。

### 3.4 分支：路径条件不是 SQL 求值屏障

IF/CASE 合并为 CASE WHEN 仅在两侧表达式、类型合并和 NULL 条件语义均获准时允许。

- JOIN ON、WHERE 和 CTE 的书写顺序都不能用作“危险表达式不会提前求值”的保证。
- 分支内 Lookup 的命中要求必须带原路径条件，不能无条件并入全局 filters。
- 三值逻辑显式按条件是否为 TRUE 判断；NULL 条件走原控制流对应路径。
- V1 依赖全定义表达式白名单保证重排安全，不依靠 CASE/CTE 或优化器当前计划屏蔽异常。

### 3.5 哑表：保留关系与行数语义

仅凭 `FROM sys_dummy/dual` 且没有 WHERE，不能删除查询：表缺失、零行或多行均可能影响原行为。

- 已存在的 FoldedQuery 语义包含行数检查，集合化不得悄悄丢弃。
- 只有关系存在、恰好一行、投影与目标转换均获证明时，才可考虑融合。
- V1 未建立对应证明时保留整个循环原执行，而不是重新引入更宽松的哑表折叠规则。

### 3.6 事务、错误与副作用

- 首版不改变任何原有事务边界；生成 SQL 前后均不自动添加 COMMIT。
- 空日志过程不能仅根据 `[Nop, Return]` 删除；实参求值、参数转换和 OUT/INOUT 写回也可能有影响。V1 不消除过程调用。
- “只读”不等于“确定、全定义、无可观察副作用”；随机数、时间、序列、递归和异常分别检查。
- 保留现有实际错误传播与顶层回滚，不添加失败后自动回退重试。
- 阶段表的 `__ok` 标记无法证明 INSERT 约束通过；后续若研究分流，应要求状态非 NULL、路径互斥且完备，但这仍不能替代事务与回放证明。

## 4. 编译架构与生命周期

### 4.1 原始产物与优化产物分离

建议在 `ir/set_oriented/` 下按职责组织分析、受限计划和代码生成。模块路径是实施建议，不要求一次创建空模块。

V1 不新增 `IrStmt::SqlSetTemplate`。执行产物复用已有 SqlExec 及被保留的外围 IR，新增能力限于编译分析和产物选择。

每个优化产物概念上包含：

| 内容 | 用途 |
| :--- | :--- |
| 原例程与循环区域标识 | 定位报告、保留原 IR |
| 原始目录/规则/对象结构有效性信息 | 防止复用过期证明 |
| 获准表达式和单行查询的类型、值域与依赖事实 | 解释为什么可转换 |
| 生成 SQL、按名绑定和物理对象依赖 | 执行与缺件校验 |
| 完整优化后 IrProg | 保留 var_types 与重定位后的控制流 |
| 转换/拒绝报告 | 可审计，不以性能推断准入 |

不在未实现前固定新的 trait 接缝。若实现发现必须修改 SqlExecutor 或 TraceSink 签名，按工程规范另行请示。

### 4.2 目录完成与失效策略

不能只使用 `set_oriented_applied: bool`：重新注册、替换被调函数、规则变化和对象结构变化均可能使旧证明失效。

1. 全量注册后，对确定的目录快照进行分析，先生成候选产物，不改原 IR。
2. 目录、规则或结构证据不再匹配时，优化产物失效；下一次调用前重新分析或选择原始产物。
3. 所有候选验证完成后才安装该版本优化结果。不适用的例程可明确标记 Skipped；优化器内部错误不得留下半安装状态，也不得伪装成正常拒绝。
4. 开关关闭直接选择原始产物；不依赖把已改写 IR 反向还原。
5. 当前 Engine 的目录、规则及执行器存在公开可变入口；仅在 register 中递增版本不够。实施时必须覆盖全部失效面，否则 V1 不跨调用复用优化缓存。
6. 对象结构证明必须与实际执行一致；若无法获得有效结构事实或排除不受控结构变更，选择原始执行，不假设部署后结构永不变化。

### 4.3 执行前顺序

```text
读取源码、规则与运行配置
  → 全量注册并保留原始 IR
  → 原始目标闭包缺件检查
  → ON 时分析目标闭包、生成候选优化产物
  → 验证结构证据、生成 SQL 依赖、绑定与 IR 完整性
  → 在产生业务副作用前选择原始/优化产物
  → 按既有 Engine::call 事务协议执行
```

该顺序同时适用于 CLI 和库调用的优化入口，不能只在 CLI 中保证“注册完成”。接口名及配置接线在实现时统一，不以文档中的伪接口当作既有 API。

### 4.4 缺件门与依赖维护

把 Pass 插在 `refuse_on_kernel_gaps` 之前不自动保证新 SQL 获得完整校验。

- 原始闭包依赖不得因优化删去查询而绕过已有缺件门。
- 使用预生成引用清单的路径，也需验证优化产物的实际物理依赖。
- 物理表、视图、序列与 CTE 局部名称明确区分；局部别名不能误报为缺件。
- 视图或调用依赖无法解析时，不给“无目标表读取”等证明。
- V1 不生成运行期阶段表，也不宣称静态缺件门能覆盖未知动态 SQL。

## 5. 分析与生成步骤

### 5.1 控制流分析

识别标准游标区域后构建 CFG，校验入口、出口、支配关系、尾回跳及外部跳入/跳出；不以扫描相邻指令作为唯一依据。

- V1 拒绝涉及异常边的区域，但分析仍需识别覆盖该区域的外层 Trap。
- 替换区域后统一重定位全部 Jump、条件跳转及外围 TrapEntry 区间。
- 保留 IrProg.var_types；验证所有目标落在合法边界，禁止旧 PC 混入新程序。

### 5.2 数据流分析

结合到达定义、必定赋值和活跃变量分析，而不是仅做“读前是否写过”：

- 每次迭代使用的临时量在该路径上已定义。
- 允许已证明不变的循环前局部值。
- 不存在 loop-carried dependence。
- 被删除的赋值、最终游标记录和属性在区域出口不活跃。
- 零行游标时，原本不执行的业务查询、赋值和写入仍不发生。

### 5.3 类型与关系证明

先建立输入值域、NULL、单行查询、目标列和依赖事实，再进行表达式替换。无法证明时记录具体原因，不生成试探性业务 SQL。

关系转换保留 bag 语义。V1 不用 GROUP BY、DISTINCT 或任意 MIN 替代逐行赋值，也不把多个原始查询的候选集合混合计数。

### 5.4 代码生成

典型产物仅为：

```sql
WITH sd_cur AS (<已验证的静态游标查询>)
INSERT INTO <目标表> (<完整列清单>)
SELECT <带必要中间类型转换的已验证表达式>
FROM sd_cur
<已验证且保持行数的关系组合>
WHERE <原流程确实决定是否插入的路径条件>;
```

- WHERE 不承载“把错误静默过滤掉”的策略。
- 不生成 LIMIT 1、INSERT OR IGNORE、通用 TRY_CAST 或异常回放 SQL。
- SQL、CTE 标识符和绑定通过结构化表示生成，保证名称隔离；禁止对任意 SQL 做字符串级变量替换。
- 原外围语句保持顺序；没有新增 TxCommit。
- 生成 SQL 经既有执行器接缝执行，DuckDB API 不得泄漏到新编译模块。

## 6. 开关、报告与既有批写的组合

### 6.1 配置

当前提供默认关闭的 `Engine::set_oriented` 和项目配置；配置值统一为布尔值：

```toml
[engine]
set_oriented = true
```

`call --file` 从源文件向上发现项目配置；多个已发现项目的配置不一致时报 ENV-0030，不猜测优先级。`call --plan` 使用计划定位的项目配置，运行态快照保留该值。配置不存在时为 false，非布尔值报错。直接 `--set-oriented` / 关闭覆盖旗标尚未实现：接入现有 Command 字段需要机械调整已有解析测试，未获测试修改授权前不另造兼容旁路。

ON 的含义是“尝试受限优化”，不是“所有目标都被集合化”。不新增 Cargo feature；不将优化框架引入运行时依赖。

### 6.2 与 batch_commit 的首版组合

| set_oriented | batch_commit | V1 行为 |
| :--- | :--- | :--- |
| OFF | OFF | 原始解释执行与即时提交契约 |
| OFF | ON | 现有 WriteBuffer 行为及其已披露偏差 |
| ON | OFF | 仅获准区域使用集合化产物，其余保持原 IR |
| ON | ON | 集合化统一拒绝，报告 BatchCommitEnabled，继续现有 batch_commit 路径 |

V1 不叠加两种优化，避免将 WriteBuffer 已知的提交/日志差异带入严格集合化证明。后续若支持组合，需要单独定义契约和测试，不能以“两个开关分别通过”推导组合正确。

### 6.3 可观测报告

报告应包含例程、区域、Converted/Skipped、证明摘要、拒绝原因、生成 SQL 及原始/优化产物关联。不要把“没有报错”作为 Converted。

建议的拒绝原因覆盖：

- NoEligibleStaticLoop / UnsupportedControlFlow / ExceptionScopePresent
- TransactionBoundaryInsideLoop / BatchCommitEnabled
- LoopCarriedDependency / LiveOutState / CursorStateObserved
- UnsupportedWrite / TargetReadDependency / UnknownObjectDependency
- UnprovenCardinality / UnsupportedCorrelatedLookup / UnsupportedTop1
- UnprovenExpression / UnprovenCoercion / UnprovenTargetConstraints
- UnsupportedCall / DynamicSql / StaleOptimizationInputs

输出统一走既有报告/trace 接缝；是否增加 explain 子命令能力按现有 CLI 结构落地，不为首版强制引入独立产品入口。

## 7. 延后能力的设计前提

### 7.1 特定异常关系化

必须显式保存错误发生点、已更新变量、未更新变量、处理器选择及恢复位置。默认赋值、跳行、重抛分别建模；存在多个潜在错误时，还需证明首先发生的错误保持一致。

正常结果、NULL 值、缺行、多行和求值错误不能混用一个布尔值表示。先用单个行为的失败测试建立规则，再扩大支持面。

### 7.2 动态模板

原来的 SqlSetTemplate 和 fallback_pc 草案不作为 V1 API 保留。后续至少解决：

- 必须是单个、受支持的查询 AST；解析成功不等于准入成功。
- 拼接片段属于值、字符串字面量、标识符还是语法片段，不能统一替换为绑定参数。
- 类型、列形状、对象依赖和目标读写关系在运行期重新验证。
- 检查阶段与实际执行分离；现有 prepare_dynamic_sql 会物化 fn_sites，不能直接作为无副作用的试探检查器。
- 仅在产生副作用前允许“不适用 → 原 IR”；开始执行后发生的错误走原异常协议，不用单个 PC 跳转冒充状态恢复。

### 7.3 异常行回放

阶段表不能预判所有约束错误，也不能保证事务回滚后仍存在。任何回放方案均需证明插入顺序、日志顺序、OUT 状态、部分持久化结果及回滚范围；禁止失败后盲目重放。

是否能在 DuckDB 当前事务能力下满足这些条件是研究问题，不在本文中承诺“正常行批量、异常行回放即可等价”。

## 8. 测试与验收门禁

### 8.1 TDD 与测试分层

按仓库规范一次锁定一个行为，先有失败测试再做最小实现。现有测试、fixture 和 golden 期望值不因优化而修改；需要变更时另行请示。

| 层 | 要验证的内容 |
| :--- | :--- |
| 纯分析单测 | CFG、必定赋值、活跃变量、类型/值域、准入与拒绝原因；不触碰 DuckDB |
| 假执行器集成 | 生成 SQL 与按名绑定、没有新增 COMMIT、原 IR 选择、依赖报告 |
| 内核探针 | 转换、NULL、数值边界、目标约束、SQL 形状及事务失败行为 |
| 进程内差分 | 同一初始快照与输入分别执行原始/优化产物，比较业务观察面 |
| CLI 契约 | 配置默认值、开关组合、拒绝/转换报告、退出码和预算说明 |

业务过程比较沿用进程内 cases 断言层，不新增外部 GaussDB 业务过程 CALL 依赖。仅比较两个模式相同还不够，关键反例也要有明确期望值，避免共同错误被当作正确。

### 8.2 首版必要行为矩阵

以下为完整首版的测试目标，名称采用 `should_...`；不是已实现清单，当前切片的实际覆盖见 §8.6：

- `should_keep_original_ir_when_set_oriented_is_off`：原始 IR 全结构、类型表、绑定和控制流保持不变，不只比较指令数。
- `should_convert_proven_static_insert_loop`：断言 Converted、生成 SQL 与结果，不允许全回退后假通过。
- `should_preserve_duplicate_cursor_rows`：不去重、不放大。
- `should_preserve_zero_iteration_behavior`：空游标不新增业务求值或状态写回。
- `should_reject_commit_inside_loop`：包含成功行后失败的场景，锁定原路径已提交数据。
- `should_reject_exception_covered_loop`：区域内和覆盖区域的外层 handler 都拒绝。
- `should_distinguish_null_from_missing_or_multiple_rows`：零行、多行查询拒绝；一行 NULL 不被默认值替换。
- `should_reject_unproven_division_and_casts`：NULL、零除数、非法日期、精度溢出不被过滤或 TRY_CAST 掩盖。
- `should_reject_unsafe_expression_in_unselected_branch`：ON/JOIN/CASE 不被当作异常屏障。
- `should_reject_live_out_and_loop_carried_state`：同时覆盖循环后读取和跨轮累加。
- `should_reject_correlated_top1_without_proof`：包含默认席位、类别优先级和排序并列。
- `should_reject_unproven_target_constraints`：批内冲突、已有数据冲突、NOT NULL 与默认值证明不足。
- `should_reject_procedure_calls_even_with_empty_body`：锁定实参求值和 OUT/INOUT 不可随意消除。
- `should_invalidate_optimized_artifact_after_input_change`：重注册、规则/结构变化及 ON→OFF。
- `should_preserve_dependency_checks_with_precomputed_refs`：原始依赖与新物理依赖均检查，CTE 名不误报。
- `should_skip_set_orientation_when_batch_commit_is_enabled`：四种开关组合有独立断言。
- `should_propagate_execution_failure_without_replay`：注入执行错误，验证传播和顶层清理，不自动重试。

purchase 与 hz 等现有业务过程在 V1 的验收重点是正确拒绝和回退；不得将“必须 Converted”写成测试期望。

### 8.3 差分比较口径

- 每次运行从相同、独立的数据状态开始，不在 OFF 已修改的数据上直接运行 ON。
- 比较返回值、OUT、业务表、重复次数、NULL、错误码/域及被约定的消息片段；涉及日志与事务的拒绝案例同时检查原执行行为。
- 无行序契约的表按完整类型化行进行规范化排序后比较，保留重复次数；有行序契约的行为不通过排序掩盖差异。
- 如使用 SHA-256，先固定类型、NULL、数值精度和序列化规则；哈希只是比较手段，不是等价证明。
- 编译语料覆盖、可执行案例覆盖和实际 Converted 覆盖分别报告。不得把语料总数写成全部业务过程的执行覆盖数。

### 8.4 工程门禁

实现阶段按 AGENTS.md 使用最小过滤测试推进，并执行 fmt、clippy、匹配 feature 的测试及提交前门禁。新增纯分析单测不依赖内核，业务差分使用现有进程内 native/cli 路径；gauss 层按既有环境要求独立报告，不以跳过冒充通过。

完整设计的验收矩阵不能由当前切片的测试替代；未实现项不得写作已验证。

### 8.5 性能验收

性能不是正确性准入条件。先在可证明的成功案例上度量，再考虑扩大业务覆盖。

必须报告：

- 代码版本、DuckDB 版本、机器、线程、数据分布、规模和缓存条件；
- 分析/生成时间、执行时间及冷启动总时间；
- 峰值内存、临时空间、SQL 执行次数、实际转换区域数量与拒绝原因；
- 多轮结果及分布，不仅提供单次最佳耗时。

原方案引用的 purchase 100k 历史数字（batch OFF 911.7s、ON 316.2s）需要原始实验条件和产物证据才能复用，不能作为 V1 转换成功或严格等价的依据。`<10s` 仅保留为未来相关业务可合法集合化后的探索目标，不是首版验收承诺。

### 8.6 当前实现切片（feat/set-oriented-v1）

**准入比完整 V1 更窄**：只分析当前顶层被调用例程，要求整个程序恰为 OPEN → FETCH record → NOTFOUND 出口 → 单条 INSERT → 回边 → CLOSE 六条指令；不抽取任意 CFG 子区域，不优化嵌套调用。记录槽不能有声明类型或与形参同名，区域外没有可被消除的指令。未命中直接保留原始解释路径。

SQL 采用 `ogsql-parser` 公共 tokenizer 的完整白名单语法，只收 `SELECT <直接列清单> FROM <单表>` 和 `INSERT INTO <单表>(<完整目标列清单>) VALUES (<当前记录字段绑定>)`。不支持别名、限定名、带引号名字、WHERE、表达式、连接、排序、LIMIT、额外子句或 fn_sites；任何剩余 token 均拒绝。生成器仅渲染已证明的结构，不替换任意 SQL 字符串。

在顶层 BEGIN 后、执行业务 SQL 前，通过现有 SqlExecutor 查询当前事务的 `duckdb_tables()` / `duckdb_views()` / `duckdb_indexes()`：

- 必须唯一定位当前数据库、当前 schema 的真实表；同名遮蔽或视图均拒绝。
- 仅收 BIGINT / INTEGER / SMALLINT / TINYINT / VARCHAR / BOOLEAN，同一复制列两侧类型必须相同；可空源不得写入 NOT NULL 目标。
- 存储 DDL 必须完全符合无默认值、无生成列、无复杂约束或排序规则的白名单；独立唯一索引也显式拒绝。源表沿用同样保守限制，不只检查目标。
- 必须写全目标列且无重复列；源与目标不能是同表。生成 SQL 中物理表完全限定，隔离 `sd_cur` CTE 名。

优化产物只含一条 SqlExec，类型表保留，原始 catalog/IR 不变。每次调用重做证明，不保留跨调用缓存；结构变化或重新注册不会复用旧产物。两个元数据查询不计作业务 SQL 往返，性能报告必须单列其开销。基础设施错误照常传播并由顶层清理，执行开始后不尝试原循环。

**当前报告**：`Engine::set_oriented_reports()` 返回本次调用的例程与 Converted（含 SQL）/Skipped（含原因），OFF 或尚未选择时为空；CLI 在 ON 时打印 `SET_ORIENTED <routine> converted` 或 `skipped reason=...`，OFF stdout 不增加内容。Converted 表示选择了集合化 SQL，不表示后续执行/提交成功；错误仍单独返回。实际生成 SQL 走已有 SqlExec trace，未修改 TraceSink 协议；证明摘要、区域映射和 explain 展示仍待实现。
